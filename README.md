## 🧩 评测体系设计

### 评测集设计

- **505 条用例**，覆盖 8 大分支、5 种测试类型、3 个难度等级
- 每条用例 17 个字段，case_id 跨版本追踪

| 测试类型 | 说明 | 示例 |
|----------|------|------|
| 单轮功能 | 基础场景覆盖 | "发货时效是多久？" |
| 边界值 | 模糊/临界场景 | "物流太慢了"（投诉？咨询？） |
| 禁止表述 | 合规红线检测 | "加我微信"（应该拒答） |
| 多轮对话 | 上下文连贯性 | 退款流程多轮引导 |
| 对抗测试 | 恶意诱导/混合意图 | "退钱还要曝光你们" |

### 双通道判分机制

```
评测输入
    ├─ 确定性预检（代码级）
    │   ├─ must_not 精确匹配 → 违规判定
    │   └─ expected_points 宽松匹配 → 要点覆盖
    │
    └─ LLM 裁判 v4.4（语义级）
        └─ 7 维度 1-5 分打分
```

### 裁判系统迭代（v4.0 → v4.3 → v4.4）

**v4.3 核心突破：行为特征判定法**

> 旧裁判犯了一个低级错误——看到"退款"两个字就判退款分支。
>
> 但实际上，"退款多久到账"是**咨询政策**（商品咨询分支），"我要退款"才是**办理动作**（退款换货分支）。
>
> 区别不在于说什么（话题内容），而在于做什么（行为模式）。

| 分支 | 行为特征 | 典型表现 |
|------|----------|----------|
| 商品咨询 | 直接解答 | 给答案、不索要订单号 |
| 退款换货 | 引导办理 | 确认意向、要订单号 |
| 订单查询 | 查询数据 | 提供实时物流/状态 |
| 投诉 | 处理追责 | 道歉、记录、升级 |

### 复评方法论（消除评测污染）

**问题：** 直接对比 V2 和 V3 的评测结果不公平——因为两个版本用了不同的裁判和用例定义。

**解法：** 用同一套 v4.4 裁判 + 修正用例，对 V2 的原始回复重新打分。

**反直觉发现：** 旧裁判系统性低估了风险——V2 幻觉率旧口径 3.0%，复评后 8.3%。

## 🔍 Bad Case 归因（从"错了几条"到"为什么错"）

知道通过率还不够，还要知道**为什么错**——不同的错因，优化方向完全不同。

**做法：** 把失败的用例逐条捞出来，设计 8 类根因分类，逐条标注统计。

**关键发现：**

- 43 条失败用例中，**72.1% 集中于分类器误路由**——问题不在模型笨，在于走错了门
- 按「影响面 × 修复难度」矩阵排优先级：误路由影响最大、修复成本相对低 → P0
- 针对性优化分类 Prompt + 边界场景处理后，**边界混淆场景通过率 63.6% → 77.3%**
- 优化效果用配对统计检验（McNemar, p<0.01）确认——排除难度混杂和随机波动

> **归因 → 定优先级 → 优化 → 统计验证**，这个闭环是本项目效果提升的核心引擎。

## 🏗️ 背景：被测系统怎么来的

### 三层漏斗架构（被测对象）

```
用户输入
    ↓
[第 1 层] 意图分类 LLM（温度 0.3）
    ├─ 知识类（疑问语气）→ 知识检索 → LLM 生成
    ├─ 办理类（祈使语气）→ 业务大类路由 → 分支处理
    ├─ 混合意图 → 核心诉求判定法 → 分流
    └─ 低置信度/闲聊 → 兜底/转人工
```

**8 个 IF/ELSE 分支：** 商品咨询 / 订单查询 / 退款换货 / 投诉 / 其他 / 多轮状态机 × 3

### 产品定位（竞品分析得出）

不做平台生态，做**面向中小商家的可定制、全渠道 AI 客服**，基于 Dify Chatflow 落地——可视化 + 开源 + RAG 内置。

### V1→V2 迭代（10 项核心优化）

**P2 路由硬错误修复（7 项）：** 咨询 vs 办理区分 / 换货场景细化 / 投诉排除规则 / **混合意图核心诉求判定法** / 改单取消纳入售后 / 其他类扩充 / 新增取消修改节点

**P3 信息完整性优化（3 项）：** LLM 润色 150→200 字 + 完整性约束 / 政策咨询关键词扩充 / 物流服务不满场景补全

## 💡 关键方法论沉淀

这个项目最有价值的不是"做了一个客服机器人"，而是沉淀了几个**可迁移的评测方法论**：

1. **复评口径** — 版本对比的公平性保障
2. **双通道判分** — 确定性规则 + LLM-as-a-Judge 的平衡设计
3. **行为特征判定法** — 从"看内容"到"看行为"的裁判认知升级
4. **Bad Case 归因闭环** — 归因 → 定优先级 → 优化 → 统计验证
5. **三层漏斗架构** — 可解释、可调试、可归因的 RAG 系统范式
