# 电商智能客服 · AI 评测体系从 0 到 1

> 这不是一个调 API 的项目，而是一套 **AI 效果验证体系**的完整实践：
> 定义"答得好" → 出题考它 → 找到错因 → 证明改进是真的。

## 📊 成果

| 指标 | V2（复评基线） | V3 | 变化 |
|------|--------------|-----|------|
| 通过率 | 91.5% | 97.0% | +5.5pp |
| 幻觉率 | 8.3% | 2.6% | -5.7pp |
| 边界混淆场景通过率 | 63.6% | 77.3% | +13.7pp |

> **口径说明**：V2 分数来自"同一裁判 + 修正用例"的复评，保证与 V3 同口径可比（见下文复评基准）。优化效果经配对统计检验（McNemar, p<0.01）确认，排除难度混杂与随机波动。

## 🧪 评测集怎么设计（505 条）

- 覆盖 **6 大业务分支 × 5 类测试类型**，含难度分级
- 每条用例 17 个字段，case_id 支持跨版本追踪
- 实物：[评测用例样例 20 条](evaluation/test_cases_sample.json)

| 测试类型 | 目的 | 示例 |
|---|---|---|
| 单轮功能 | 基础能力保底 | "发货时效是多久？" |
| 多轮对话 | 上下文连贯性 | 退款流程多轮引导 |
| 边界值 | 模糊/临界场景 | "物流太慢了"（投诉还是咨询？） |
| 对抗测试 | 恶意诱导 | "退钱还要曝光你们" |
| 禁止表述 | 合规红线 | "加我微信"（应拒答） |

## ⚖️ 怎么判分：双通道

- **确定性预检（代码级）**：must_not 精确匹配 → 违规判定；expected_points 宽松匹配 → 要点覆盖
- **LLM 裁判 v4.4（语义级）**：7 个维度 1-5 分打分

### 裁判迭代的关键一跃：行为特征判定法（v4.3）

旧裁判看到"退款"两个字就判退款分支——但"退款多久到账"是**咨询政策**，"我要退款"才是**办理动作**。区别不在说什么（内容），而在做什么（行为）。

| 分支 | 行为特征 |
|------|---------|
| 商品咨询 | 直接解答，不索要订单号 |
| 退款换货 | 确认意向、引导给订单号 |
| 订单查询 | 提供实时物流/状态 |
| 投诉 | 道歉、记录、升级 |

## 🧯 复评基准：让版本对比公平

直接拿旧裁判评的 V2 分数对比新裁判评的 V3，会因"裁判变了 + 用例变了"产生虚高——这叫评测污染。

**解法**：用同一套 v4.4 裁判 + 修正用例，对 V2 的原始回复重新打分，作为新基线。

**反直觉发现**：旧裁判系统性低估风险——V2 幻觉率旧口径 3.0%，复评后 8.3%。不消除评测污染，优化就是自欺欺人。

## 🔍 Bad Case 归因闭环

通过率只能告诉你"错了几条"，归因才能告诉你"为什么错"。

1. 43 条失败用例 → 8 类根因逐条标注 → **72.1% 集中于分类器误路由**
2. 影响面 × 修复难度矩阵排优先级：误路由影响最大、修复成本低 → P0
3. 针对性优化后：边界混淆场景 63.6% → 77.3%
4. McNemar 配对检验 p<0.01：提升显著，不是碰巧

> **归因 → 定优先级 → 优化 → 统计验证**，这个闭环是本项目效果提升的核心引擎。

## 🏗️ 背景：被测系统（10 秒版）

电商客服机器人：三层漏斗架构（意图分类 → 路由检索 → 生成执行），8 个业务处理分支（含多轮状态机），基于 Dify Chatflow。产品定位来自竞品分析：面向中小商家的可定制全渠道 AI 客服。

3. **行为特征判定法** —— 裁判从"看内容"升级到"看行为"
